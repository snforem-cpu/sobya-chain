Verify SOBYA records from your app.

A read-only JavaScript client for checking SOBYA Proof and Invoice Proof records directly against SOBYA Mainnet.

CURRENT STATUS

Developer preview

IN DEVELOPMENT

The first implementation is a browser-native ES module. It does not require a wallet, API key, subscription, or transaction signing. It reads public blockchain data through SOBYA EVM JSON-RPC.

Important: this is a client SDK, not a hosted REST server. GitHub Pages is static hosting and cannot execute server-side API routes. The SDK talks directly to the public RPC endpoints.

01 · INSTALL / IMPORT

Verify a document proof

import { createSobyaVerifyClient } from "./verify-api/client.js";

const sobya = createSobyaVerifyClient();
const result = await sobya.verifyProof({
  txHash: "0xYOUR_TRANSACTION_HASH",
  file: document.querySelector("#file").files[0] // optional
});

if (result.valid && result.match === true) {
  console.log("File matches the on-chain fingerprint");
}

02 · INVOICE PROOF

Verify an invoice record

const result = await sobya.verifyInvoiceProof({
  txHash: "0xYOUR_INVOICE_TRANSACTION_HASH",
  file: invoiceFile,
  metadata: {
    reference: "INV-2026-0042",
    issueDate: "2026-11-27",
    amount: "1250.50",
    currency: "USD",
    issuer: "Supplier",
    recipient: "Customer"
  }
});

Supply the original invoice file and the exact metadata used when registering it. All fingerprint calculations happen locally.

03 · RESPONSE

Understand the result

  • valid: true — a successful SOBYA Proof Registry transaction with the exact 1 SOBY fee and matching event.
  • match: true — the supplied file (and invoice metadata, where applicable) reproduces the recorded fingerprint.
  • match: false — the on-chain record is valid, but the supplied data differs.
  • match: null — the transaction is valid; no file comparison was requested.

A blockchain match does not prove document truth, legal ownership, issuer identity, invoice payment, delivery, or legal/tax compliance.

Privacy and security

The SDK never uploads documents or invoice details, never requests wallet access, and never broadcasts transactions. It checks SOBYA Mainnet chain ID, registry destination, transaction success, exact service fee, call data, and the matching registry event. RPC availability and browser CORS remain external dependencies.
